# 로드맵 — 단계별 구축 계획

> 관련 문서: [서비스 기획서](./01-service-plan.md) · [기술 스펙](./03-tech-spec.md)

각 단계는 "목표 → 산출물 → 완료 기준(Exit Criteria) → 주요 리스크" 순으로 정리했다. 소요 기간은 확정 일정이 아니라 상대적 규모 감각을 위한 참고치이며, 실제 착수 시 재산정한다. CI/CD 트랙은 전 단계에 걸쳐 점진적으로 확장되는 별도 축으로 함께 표시했다.

## Phase 0 — 기획/검증 (현재 단계)

- **목표**: 서비스 정의, 프라이버시 원칙 확정, 최소 1~2개 제조사의 발주 양식(엑셀 헤더/폼 구조) 실물 확보.
- **산출물**: 기획서/로드맵/기술 스펙(본 문서들), 제조사 매핑 원본 샘플, 파일럿 안경원 후보 1~2곳 컨택.
- **완료 기준**: 최소 1개 제조사의 발주 양식 구조를 손에 넣고, SPH/CYL/AXIS/ADD/PD → 해당 양식 매핑표를 수기로라도 완성할 수 있는 상태.
- **리스크**: 제조사 양식 확보 자체가 폐쇄적 B2B 포털 특성상 가장 큰 병목이 될 수 있음 — 커뮤니티/지인 네트워크 의존도가 높다.
- **CI/CD 트랙**: 없음(코드 없음).

## Phase 1 — MVP: 단일 제조사 변환기

- **목표**: 처방 데이터 1회 입력 → 단일 제조사 엑셀/양식 자동 생성까지의 핵심 가치를 가장 좁은 범위로 증명.
- **산출물**:
  - 로컬 에이전트 최소 버전(로컬 웹 UI, 처방 입력 폼, 로컬 SQLite 고객 DB, 엑셀 변환 다운로드).
  - 클라우드 매핑 API(비식별 — 처방값+제품코드만 받아 매핑 결과 반환).
  - 자동 제출(Selenium/Playwright)은 이번 단계 제외 — 변환된 파일을 안경사가 직접 업로드하는 방식으로 리스크를 낮춘다.
- **완료 기준**: 파일럿 안경원 1곳에서 실제 발주 1건을 변환기로 처리 완료.
- **리스크**: 제조사 양식이 예고 없이 바뀔 수 있음 → 매핑 규칙을 코드에 하드코딩하지 않고 버전 관리되는 데이터로 분리(기술 스펙 참고).
- **CI/CD 트랙**: GitHub Actions 기본 CI(lint/test) 세팅.

## Phase 2 — 제조사 확장 + 자동 제출

- **목표**: 대응 제조사 2~3곳으로 확장, 매핑 규칙을 관리자 콘솔에서 코드 배포 없이 업데이트 가능하게 전환, 자동 제출(Selenium/Playwright) 도입.
- **산출물**: 매핑 룰 엔진(버전 관리), 내부 관리자 콘솔(매핑 편집 화면), 로컬 에이전트의 자동 제출 모듈, 제조사 포털 계정 정보 로컬 암호화 저장(vault).
- **완료 기준**: 신규 제조사 매핑 추가가 에이전트 재배포 없이 룰 데이터 갱신만으로 반영됨.
- **리스크**: 제조사 포털의 로그인/캡차/세션 정책 변화에 자동화가 취약할 수 있음 — 실패 시 수동 폴백(Phase 1 방식)을 항상 유지.
- **CI/CD 트랙**: 클라우드 백엔드 컨테이너화(Docker) + main 브랜치 merge 시 자동 배포.

## Phase 3 — 로컬 CRM: 렌즈 교체주기 알림톡

- **목표**: 로컬 고객 DB 기반 교체주기 계산 + 안경사 명의 카카오 알림톡 발송.
- **산출물**: 교체주기 계산 로직(고객군별 규칙, 예: 소아 6개월/성인 12~24개월), 로컬 스케줄러, 카카오 비즈니스 채널·발신프로필 연동 가이드, 발송 경로 A안(로컬→발송대행사 직접) 구현.
- **완료 기준**: 파일럿 안경원에서 실제 고객에게 알림톡 발송 성공 및 서버 로그에 고객 PII 미기록 확인(감사 완료).
- **리스크**: 카카오 비즈니스채널 개설, 발신프로필 심사, 알림톡 템플릿 사전 검수에 실무 리드타임(통상 수일~수주)이 소요됨 — **이 단계 착수 최소 2~4주 전에 채널 개설/템플릿 심사를 선행**해야 한다.
- **CI/CD 트랙**: 배포 파이프라인에 비식별 로그 스캔(전화번호 패턴 탐지 등) 게이트 추가.

## Phase 4 — 로컬 에이전트 Fleet 관리

- **목표**: 관리 대상 안경원이 늘어나는 것을 전제로 에이전트 버전/헬스/설정을 원격 관리.
- **산출물**: Fleet 관리 콘솔(에이전트 등록/버전 분포/헬스 대시보드), 에이전트 자동 업데이트 메커니즘, 라이선스/구독 상태를 heartbeat로 전달하는 구조.
- **완료 기준**: 신규 에이전트 버전을 배포하면 파일럿 그룹 에이전트들이 자동(또는 승인 후) 업데이트됨을 확인.
- **리스크**: 다양한 Windows 환경(구형 OS, 백신 오탐 등)에서의 설치/업데이트 안정성.
- **CI/CD 트랙**: 태그 push 기반 에이전트 빌드/서명/배포 파이프라인 구축(기술 스펙 6장 참고).

## Phase 5 — 과금/구독 및 확장

- **목표**: 안경원 계정/라이선스/과금 모델 도입, 다수 안경원으로 확장 세일즈.
- **산출물**: 구독 플랜, 결제 연동, 안경원 온보딩 셀프서비스 플로우.
- **완료 기준**: 유료 전환 안경원 N곳 확보(목표치는 별도 협의).
- **CI/CD 트랙**: 스테이징/프로덕션 환경 분리, 배포 승인 절차 도입.

## Phase 6 — 고도화

- **후보 항목** (우선순위는 추후 결정):
  - 기존 POS 연동(가능한 벤더부터), CSV import 고도화.
  - 재고 회전/재주문 인사이트 등 비식별 통계 대시보드(안경원 자체 데이터는 로컬에 남기고, 집계 지표만 옵트인으로 공유하는 구조 검토).
  - 체인 안경원을 위한 다지점/직원 권한 관리.
  - 알림톡 외 채널(문자 등) 확장.
